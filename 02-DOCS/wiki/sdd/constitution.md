# CRM — Constitution

> Version: v1.0.0 · Ratified: 2026-11-22 · Last amended: 2026-11-22
> Goal: a CRM for a team, fed by the website digital-system-pros.vercel.app.
> The non-negotiable principles every rsc-sdd phase obeys. Stack mechanics live in
> `02-DOCS/wiki/stack/*` (created as each stack piece lands); this file ratifies the principle.

## 1. Stack canon

1. TypeScript (`strict: true`) on Node.js 22 LTS. Version pinned in `package.json` `engines` + `.nvmrc`.
2. Frameworks fixed: **Next.js (App Router)** deployed on **Vercel**; **Supabase** for Postgres,
   Auth and Storage; Tailwind CSS for styling. Changing one is a MAJOR amendment.
3. Package manager: **pnpm**. One lockfile (`pnpm-lock.yaml`), committed.
4. Database schema changes ship only as versioned Supabase CLI migrations in `supabase/migrations/`;
   no manual edits in the dashboard.

## 2. Quality bar

5. Code is formatted (Prettier) and lint-clean (ESLint, zero warnings) on every commit; CI fails otherwise.
6. `tsc --noEmit` passes with zero errors before merge; no `any` without a justifying comment.
7. TDD (red → green → refactor). Line coverage ≥ **80%** on changed code (Vitest + Testing Library).
8. Critical flows have a Playwright E2E test that gates merge: lead capture, login, role access,
   pipeline stage change.
9. All external input (forms, API bodies, webhooks, env vars) is validated with a Zod schema at the boundary.

## 3. Conventions

10. Structure by feature: `src/features/<domain>/` (leads, contacts, companies, pipeline, tasks,
    email, dashboard, auth); shared code in `src/lib/`. Source files ≤ 800 lines.
11. Every API route returns the envelope `{ success, data, error }` with correct HTTP status codes;
    errors never leak stack traces or SQL.
12. Commit messages: gitmoji + Conventional Commits — `✨ feat(leads): capture website form`.
    Enforced by `.rsc/gitmoji-guard.mjs`.

## 4. Branching & shipping

13. Work happens on a branch off `main` (`feat/…`, `fix/…`, `chore/…`); merge via PR after CI is green.
    No direct pushes to `main`. Enforced by `.rsc/branch-guard.mjs`.
14. **Git authorship is the human's.** No `Co-Authored-By` an AI, no "generated with" footer.
    Enforced at the `ship` phase.

## 5. Security & privacy floor

15. No secret is ever committed. Secrets live in `01-TOOLS/<provider>/.env` / `.env.local`
    (gitignored) and in Vercel env vars. The Supabase **service-role key is server-only**, never
    in client bundles or `NEXT_PUBLIC_*`.
16. **Row-Level Security is enabled on every table**, with policies per role (`admin`, `sales`).
    A table without RLS policies is a blocker. Roles are checked server-side, never trusted from the client.
17. The public lead-intake endpoint is the only unauthenticated write: Zod-validated, rate-limited,
    CORS restricted to the website origin, and spam-protected (honeypot + Cloudflare Turnstile or equivalent).
18. Leads and contacts are personal data: collect only what the form needs, never log PII, and
    support deleting a contact on request.
19. Dependencies: no new package without checking maintenance and license; `pnpm audit` has no
    high/critical findings at merge. Baseline: `security-audit`.

## 6. UX / accessibility floor

20. WCAG 2.2 AA: keyboard-navigable, visible focus, labelled form fields, contrast ≥ 4.5:1.
    Usable from 360 px wide.

## 7. Performance budgets

21. CRM pages: LCP ≤ 2.5 s on a mid-range laptop over 4G; lists paginate (≤ 50 rows per request).
22. Lead-intake endpoint: p95 ≤ 500 ms; email sending and calendar sync never block it (run async).

## 8. Knowledge & decisions

23. Every significant decision is appended to `02-DOCS/wiki/sdd/decisions.md` (date, options,
    why). The constitution is the highest-order decision record.

## Definition of Done (the merge bar `verify` runs against)

A change ships only when ALL hold:

- [ ] Prettier + ESLint clean (5); `tsc` passes (6).
- [ ] Tests written first and passing; ≥ 80% coverage on changed code (7); E2E for touched critical flows (8).
- [ ] Input validated at the boundary (9); conventions and API envelope followed (10-12).
- [ ] Schema changes are migrations (4) with RLS policies (16).
- [ ] On a branch, merged via PR, authored by the human (13-14).
- [ ] No secret committed; security floor met (15-19).
- [ ] Accessibility and performance budgets met where the change touches UI or the intake endpoint (20-22).
- [ ] Significant decisions logged (23).
